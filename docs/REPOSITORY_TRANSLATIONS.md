# 译文仓库与原文映射

GitHub Markdown 仓库使用现有整站导入队列。订阅页选择“GitHub Markdown 仓库”，填写公开仓库、分支、正文根目录与对应网站；保存后随每天 06:00 的来源检查运行。首次读取全目录，以后按固定提交和现有正式文件复用，已有正文与阅读批注保持不变。

仓库导入仅使用原文直接入库模式：保留现成译文，不再次翻译或生成导读。按固定提交下载快照，使用 Git tree 核对文件数量和每个 blob 的 SHA-1，拒绝截断目录、缺失文件、符号链接和越界路径。Markdown 目录层级映射到阅读区内相同子目录。空文件和 SUMMARY 导航记录为排除项；文章中的相对资源链接转换为固定提交资源或对应网站链接。

## 来源关系

- `source_url` 标识实际阅读的译文，继续用于发布去重。
- `original_url` 来自明确原文字段，或正文开头与原文件名／标题完全一致的独立链接。
- `fact_source_url` 将原文和译文归到同一事实来源。两种语言各自保留正式文件，不因归到同一来源而丢失一种正文。
- 已有本地原文时，译文同时记录 `original_document_path`。完整证据及原文、译文的当前路径保存在已有应用数据区的 `.local-ir/source-relations.json`。

多个原文候选仍不明确时保留待确认状态；正文引用、作者主页及仅凭相似标题猜出的地址不作为原文。不会为了导入译文而获取全部原文。

`GET /api/source-relations?url=<原文或译文 URL>` 在本机查询同一来源的两种表示。返回 `original_fetch_required`，供后续导出按需获取原文；返回原文链接不等于已经完成段落级高亮对齐。查询重新核验本地原文是否仍存在。

## 验证

`node --test tests/repository-import.test.mjs` 使用隔离材料检查字段歧义、目录保留、来源关系、本地原文保护、固定恢复编号、快照哈希与 Windows 长路径。

真实导入必须核对整站运行记录、所有正式文件哈希、来源正文覆盖和映射证据。HTTP 202 或订阅已保存仅代表受理，不代表整站完成。
