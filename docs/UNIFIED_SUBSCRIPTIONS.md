# 统一订阅与渐进阅读

订阅集中在现有渐进阅读本地网页维护。RSS、B 站和知乎共用材料登记、去重、运行状态及日报周报，继续复用现有内容处理流程。

订阅按来源类型分组，可展开和收起。“已停用的订阅”分区默认收起，支持重新启用或直接删除。删除会移除订阅配置，已导入的正文、批注和报告保留。

## 处理模式

- 标准流程导入：自动进入现有标准处理与阅读区发布流程。
- 原文直接导入：文字来源只提取正文与转换 Markdown，不调用模型；视频不提供此模式。
- 日报与周报：长文先生成筛选卡，选中后入库。文字短文按 1,200 个有效字符分流，每篇通过标准处理后即追加到北京时间当周的短文周报。

前两类在日报、周报中附带新入库动态；第三类提供待筛选卡片。首次安装由用户配置来源，不附带开发者订阅。

B 站订阅支持指定视频分 P 和合集。视频筛选卡使用完整字幕，选中后再运行现有截图、图文正文和标准导读。无字幕时保留等待，不把简介当作全文。

知乎适配层支持指定作者的新回答、文章与指定专栏。列表和正文均按实际请求地址复用现有 Chrome 登录快照，不隐式退回匿名访问。专栏采集复用 [RSSHub 专栏路由](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/zhihu/zhuanlan.ts)使用的专栏域名 API，并保留置顶文章、分页完整性和日期校验。作者端点参考维护中的 [RSSHub 回答路由](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/zhihu/answers.ts)与[文章路由](https://github.com/DIYgod/RSSHub/blob/master/lib/routes/zhihu/posts.ts)，携带与现有正文抓取相同的请求标识。作者分页地址仅在域名、作者和接口路径一致时从 HTTP 升级到 HTTPS；鉴权失败、越界分页及无法继续的分页仍报错。作者列表唯一条目数与平台总数不符或采集期间总数变化时，只记录非阻断异常并保留两者数量，已获取内容继续进入渐进阅读及日报、周报流程，不宣称历史全量完整。列表发现与单篇正文获取分别核验，不能用列表请求失败推断正文无法获取。

专栏订阅同时接收专栏内的文章和回答。订阅检查中的专栏数量差异沿用非阻断异常规则，已获取正文继续处理；单次专栏全量导入仍保持原有严格数量校验。

## 更新与历史

每个订阅可沿用现有范围、设定最早发布日期或选择不限时间。日期从北京时间当天零点起算。有日期下限时，发布时间未知的条目不参与补收。保存后，下一次检查或生成报告会应用范围。RSS 会复用符合范围的本地 Feed 快照和正文缓存。B 站与知乎的补收范围取决于平台能列出的内容和访问权限。

同一原文只建立一个材料条目，保留多个订阅归属。发现原文修订时提示更新，保留已入库正文、高亮、批注和原有选择，不自动重新加工。标准处理与原文模式冲突时仅暂停对应文章，在网页选择一次。

## 日报与周报

报表继续使用 Markdown。新候选在日报中勾选。未勾选和多选的条目随新一期长文周报滚动，选框全部恢复为空。旧周报的选框和状态失效，旧条目链接到当前入口。勾选保存稳定后约一分钟内自动入队。

日报中的所有篇目处理成功，且已过日报当天时，整份文件移入 `待归档原文/订阅/日报`。生成新长文周报时，先汇总日报和旧周报里的未决篇目，确认收录后将旧报告移入对应的日报或长文周报归档目录。当日日报保留到次日。失败的入库动作继续保留待处理状态。

短文每篇有一个“已完成阅读”选框，中英文正文共用这个完成状态。进入新一周后的首次来源处理或报告生成会执行平移。已勾选的篇目连同批注追加到 `待归档原文/订阅/短文/<订阅源名称>.md`，未勾选的篇目使用保存的 Markdown 移入新一周，保留正文修改、中英文批注及选框。修改正文而未勾选的篇目仍会平移。每个订阅源维护一份持续追加的短文归档文件。

旧短文周报在完成转移后退出阅读区，原文件保存在内部历史目录用于恢复。归档和平移按篇目与来源版本去重，中断后继续核对已完成的转移。旧报告的后续编辑不会改变当前篇目的状态。

RSS、知乎和 B 站分别在北京时间每天 06:00、07:00 和 08:00 检查。日报每天 09:00 生成，长文周报每周日 21:00 归并。短文周报随处理结果更新。

来源提供发布时间时，日报和周报在每条内容末尾以北京时间显示该信息。

全部合格条目持久排队，低并发处理，不设置每日条数上限。每个来源的周期检查同时重试该来源的堵塞项，每条每周期最多一次；先核对回执和缓存，复用已成功步骤，保留失败证据。

队列与运行记录提供一次性手动重试，检查和重试的入队状态、运行阶段与结果显示在按钮附近。

有新报表或新故障时发出本机通知，同一故障不反复提醒。错过定时运行后补查当前来源，不伪造错过日期的历史报表。

## 验证

`node --test tests/subscriptions.test.mjs` 使用隔离合成材料检查队列、去重、修订保护、报表和恢复。真实来源访问与调度须按当前安装单独核验。

## 运行与恢复

本地页面为 `http://127.0.0.1:37829/subscriptions`，由原渐进阅读服务提供。订阅注册表、持久任务队列、监测状态和通知记录保存在 `D:/AppData/ProgressiveReading/Subscriptions`；原 RSS 和视频账本继续使用。配置中的名称、模式、启用状态和阅读区目录通过页面编辑，原 `RSS 自动导入.md` 仅保留为迁移来源。

Windows 任务计划程序负责定时投递，原本地服务负责执行。原视频任务改为投递统一队列，旧 RSS 五分钟轮询任务继续停用，不另开常驻采集服务。任务运行失败后保留分步回执，程序中断后重启会继续尚未完成的持久任务。每个来源周期对失败项只重试一次，已完成正文不重新生成。

`node subscription-workflow/cli.mjs status` 查询状态；`node subscription-workflow/cli.mjs enqueue --kind rss|bilibili|zhihu|daily|weekly` 投递任务；`node subscription-workflow/cli.mjs drain` 在本地服务不可用时继续现有队列。CLI 与原 RSS 命令共用互斥锁，避免同时修改筛选账本。

切换前的原配置、运行账本、报告及任务 XML 保存在 `D:/Artifacts/ProgressiveReading/subscriptions-20261106/`。恢复时先停用统一来源与报表任务，暂停统一注册表，再核对正在运行的导入并恢复原任务 XML。不要把旧账本覆盖到已经新增内容的运行目录；应按切换前后回执合并，以免丢失新决定。
