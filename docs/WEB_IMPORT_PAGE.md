# 网页链接导入首版

更新：2026-09-14。网页导入页、高级导入规则清单和知乎专栏全集规则已启用；真实 Chrome 页面已验收。持续 Cookie 同步已恢复，原知乎专栏 7/7 篇正式落盘并通过文件哈希校验，证据见下方。

## 使用

现有本地服务的页面路径是 `/import`，默认地址 `http://127.0.0.1:37829/import`。原根页面 `/` 和旧 `/api/import` 保留。

1. 粘贴混合文字、Markdown 链接或裸 URL。预览会显示识别与去重后的条目；单批超过 50 个时禁止提交并提示分批。
2. 如有加工要求，在独立的可选输入框中填写，然后点击“导入到阅读区”。链接周围的普通文字不自动作为加工指令。
3. 查看逐条排队、抓取与加工、成功、质量警告、失败、需要登录或网页渲染的结果。成功项显示后端核定的文件路径。
4. 连接中断时点击“继续提交 / 查询”；恢复联网或刷新同一标签页也会继续查询。请求保存于当前浏览器标签页的 sessionStorage，关闭标签页后的恢复不作保证。
5. 当前尝试结束后可“重试此项”或“重试失败项”。此前的失败原因保留在“请求与重试记录”中。
6. 页面顶部显示[导入规则清单](IMPORT_RULES.md)。知乎专栏自动展开全部文章（含置顶），超过 50 篇自动分批；展开后可以查看每篇文章的状态。重试专栏时，已成功文章仍由后端复用。

“已导入”要求逐条结果为 `imported` / `imported_with_warnings` / `idempotent_replay`，且包含正式 Markdown 路径、SHA-256、标准预处理状态与 `ready` / `warning` 质量回执。页面展示后端回执；测试还独立读取了磁盘文件并校验哈希。HTTP 202 仅表示受理。警告不等同于无警告成功，缺失落盘回执显示“待核实”。

## 接口与边界

- 前端只调用现有 `POST /api/browser-import/requests`、`GET /api/browser-import/requests/:requestId` 和只读健康接口；没有独立后端或构建技术栈。
- `source: "web_import_page"`，`entry_route: "obsidian"`。目录由后端按域名选择；页面不接受任意输出路径。
- 链接解析使用 `scripts/url-import-input.mjs`，与服务共享；保留 Obsidian 的来源 URL 与去重规则，补齐相邻 Markdown 链接、反引号、中文标点和相邻分隔链接的边界。
- 每次尝试在首次 POST 之前保存 `client_request_id`。同一次尝试因连接失败或刷新重复提交时沿用 ID；收到服务 request ID 后只做 GET。后端终态请求不可变，用户明确重跑失败条目时使用新的尝试 ID，仅包含失败条目，并保留原回执。
- 后端以规范化来源 URL 全局复用已有正式文件，入口目录差异不再导致重复正文。已知正文哈希变化、现有文件或 sidecar 无法安全复用时，URL 导入失败并保留原材料；不覆盖正文、标注或人工优先级。
- 未扩展订阅、上传、阅读加工、排期或 RemNote 导出。未更改浏览器/Obsidian 插件部署。

实际运行状态以本机健康接口和来源返回为准。公开源码不附带私人材料与历史运行回执；合成回归入口见 [安装与兼容性](SETUP.md)。
