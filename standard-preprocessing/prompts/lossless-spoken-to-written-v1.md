# 信息无损口语转书面清洗合同 v3

目标不是摘要、代写或润色成另一种人格，而是让读者无需回到转写稿，也能获得全部有效信息的结构化书面正文。

优先级：

1. 原始信息与真实意图；
2. 原说话者的视角、立场、术语和判断力度；
3. 清晰书面表达与结构可读性。

保留视角和立场不等于保留口头句法。有效信息无损，表达必须重新组织；不能因为担心字数下降而把口述绕行、同义复述、现场串场重新填回正文。

硬规则：

- 每个输入 source block 必须且只能映射一次，不得通过删块制造“清洗完成”。
- 保留全部实质观点、条件、例外、例子、数字、专名、术语、比较对象、结论和不确定性。
- 人物身份与关系、所在地点、时间、选择或申请所处状态、可能性判断等情境背景属于实质信息，必须保留。
- 原文逐项列举的人物、机构或原因不能擅自压成“环境不好”等泛化概括；强烈、尖锐或攻击性的措辞不得中和成温和表达。
- 缩写、网络词、圈内语、中英混用、攻击性措辞和强弱程度默认保留，不擅自中和或强化。
- 只修有充分依据的 ASR 错误，只删除不承担语义、态度、回应或情绪作用的口头填充、机械重复和纯现场流程语。称呼、确认、致谢与提问是否可删，按其在原文中的作用判断，不按词表机械删除。
- 重复表述中的新增信息、限定和力度必须保留；紧邻且对象、动作、条件和力度完全相同的操作指令只保留一次。有教学内容的重复解释、不同方法和推导过程不能当作冗余删除。
- 把相邻问答、插话和字幕碎片合并为语义完整的书面段落；问题中的有效背景必须进入正文，不能连同问句一起丢失。
- 书面正文将问答中的实质内容与条件组织为连贯表达，删除仅用于维持现场流程、没有内容作用的会话操作；有态度、反问、互动结论或情境作用的表述须保留。
- 保持原说话者直接陈述的视角；不得改成“作者认为、说话者指出”等第三人称转述稿。
- 只可新增不携带新判断的导航标题。不得新增外部事实、解释、建议、论据或结论。
- 不得把原文案例推导成原文没有明说的通用原则；即使推断看似合理，也不能进入清洗正文。
- 明显同音字或断句错误可以修正；不确定的人名、机构、术语和事实保留原状，不靠模型记忆补全。
- 代码、伪代码、URL、LaTeX、行内代码和审查占位符必须原样保留。
- 清洗后正文应与原文信息体量相当；不能用更短的概览替代全文。

结构化与书面化（对齐 AudioWorkflow/prompts/refine-non-writing.md 的保真和非写作规则，保留本合同自己的章节与来源映射格式，不调用写作决策）：

- 把长口语编译为通顺完整的结构化大纲，不只是加标点、加标题后照抄字幕。各节以内容型 ## 标题导航；一般正文用 Markdown 多层 - 列表，每层缩进两个空格。
- 顶层节点陈述具体观点、步骤或问题；原因、解释、例子、数字、条件、限制、反对意见和行动归入对应节点。只按原文明确的逻辑建立层级，不虚构因果或类别。公式、Mermaid 和真正代码继续使用原语法，不强制改成列表。
- 先读完相邻片段再整理，合并同一信息的重复表达和自我复述；具有不同条件、数字、对象或结论的相似句仍须分别保留。重复带来的强调力度可以保留，不能靠重复整句话实现。
- 把没有新增含义的反复起句、指代绕行和纯铺垫整理为直接、完整的陈述。指代、步骤顺序、定义、对比和自然表达有实质作用时必须保留，不能按固定案例或关键词替换。
- 将整组相邻来源组织为可直接阅读的完整句，保留原有判断力度、程度、频率、时间感和自然措辞。副词、限定词、语气和连接词只在确认没有信息或表达作用时删除；不能因删后仍通顺就认定多余。讲解按概念、条件、原理、推导、例题与结论组织，保留中间步骤和不同方法。
- 同一审核范围内，同一事实只陈述一次，把不同的支持信息归到该事实下。即使原文隔了几个节点才复述同一意思，也要合并；不同阶段、对象、条件或例外必须保留，不能借去重删掉有效信息。
- 一个节点应能独立理解：不能只写“这是知识”“这就是我们的竞赛”“还有这个东西”等口头承接，也不能先重复标题再逐句解释。将承接意图并入实际观点；长串现场指示改为材料或操作本身的具体说明。
- 删除对现场听众的确认和纯主持流程；真正有关的提问、作业要求、互动结论或材料展示信息须转为正文。原有第一人称经历、判断和尖锐表达不改成旁观者报告。
- 合理连接残句限于上下文明示的信息。不能补写未知专名、外部事实、未明说的建议或推论；不能把可能、计划、假设写成确定或已完成。
- 不增加“原话、疑点、未完、待确认、整理说明”等编辑栏目；原文自身的疑问、未完成状态和不确定性属于有效信息，应在相应观点中保留。
- 一节已有具体主题标题时，不再用同义的顶层列表包裹全部内容；直接排列实际观点，并将其支持信息放入下一层。不得把每个字幕段机械变成独立同级标题或长列表项。
- 输出前自检：是否仍像现场逐句说话；是否还有相邻同义复述；原因和例子是否实际归属对应观点；数字、案例、反例、限制、行动和不确定性是否全部保留。

审计要求：

- 每个输出章节列出按原顺序覆盖的 source_block_keys。
- 结构化、合并或语气规整过的原句由本地 artifacts 保存，最终阅读 Markdown 只呈现清洗后的正文。
- 本地校验器负责覆盖、顺序、长度、保真、受保护语法、可见时间码、会话噪声和确定性锚点；校验失败时必须按错误重试，不得降格冒充通过。
