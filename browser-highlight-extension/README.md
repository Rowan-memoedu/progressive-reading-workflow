# Local IR Browser Highlight

这是 Local IR 的浏览器端加工扩展。v0.5.17 与 Obsidian Local IR 共用同一份文档核心和 `local-ir.document-state/v1` 状态合同。扩展只在用户点击“初始化加工”或“导入本地”后创建网页草稿；未初始化页面不会生成草稿状态。加工过程使用虚拟高亮，未保存时不会创建 Markdown 文件，也不会把浏览器高亮语法写进正文。

工具框为可移动悬浮框：拖住左侧把手移动，松开后记住位置，刷新和新页面会恢复。缩小窗口或展开控件时保持在可见范围内；把手聚焦后可用方向键微移，按住 Shift 加大步幅。

“导入本地”只创建提交所需的持久草稿，不等同于“初始化加工”。无论导入成功还是失败，加工模式、挖空模式、完成阅读等加工控件都保持收起；失败后原“导入本地”位置改为“重新导入”，并继续与“初始化加工”并列。只有用户明确点击“初始化加工”后才展开加工控件。

在加工模式或挖空模式开启时，按住 `Ctrl` 单击正文段落会直接选中整段并创建对应虚拟标注；普通单击正文不触发整段标注。按住左 `Alt` 依次单击两条已有高亮，仍按原流程执行手工合并。

## 功能边界

浏览器端负责：

- 整页来源快照与 Readable Markdown 转换输入；
- 手动初始化每个需要加工的网页；
- 以与 Local IR 一致、全局互斥的“加工模式 / 挖空模式”创建虚拟标注；
- 批注类型、改写、随想、问答卡、合并和撤销；
- 手动保存、关闭标签页提交、浏览器下次启动重试；
- `导入本地` 一键执行初始化、标准 Markdown 预处理和阅读区保存；
- 右键“导入当前页到渐进阅读”直接复用页面内“导入本地”的初始化、页面快照、标准预处理、保存和草稿状态流程；
- 右键“导入链接到渐进阅读”和 Obsidian 链接输入都只向同一个网络导入 broker 提交请求；共享执行器先调用后台标准 URL 直抓，全程不创建可见或非激活标签页；两种浏览器右键入口仍会在原页面持续显示处理中、成功或失败反馈，并用扩展角标同步状态；
- URL 提交入口的抓取由服务端静默执行器完成；该入口只提交 URL 并展示统一回执，不领取 broker 抓取任务、不处理浏览器凭据，也不负责初始化或启动本地服务。页面内“导入本地”及复用它的右键动作则提交 Chrome 已加载的页面快照，详见下文；
- 服务端回执为 `requires_browser_auth` 或 `requires_js_render` 时，扩展只显示该明确降级状态，不尝试浏览器补抓、不执行页面 JavaScript，也不打开可见或非激活标签页；
- `完成阅读` 时把普通保存路径的根目录从 `阅读区/` 替换为 `待归档原文/`，因此目标为 `待归档原文/浏览器高亮/`。

浏览器端不负责阅读池、优先级或批量归档编排。保存、自动提交、完成阅读与“导入本地”全部调用同一标准渐进阅读预处理和写入流程，仅携带不同的处理选项。直接保存关闭正文改写、结构化、翻译和导读，不调用模型；“导入本地”显式开启导读，其余选项沿用标准流程。公式兼容处理、来源审计、批注重新锚定、内容哈希和人工修改保护由同一实现负责。

## 草稿与保存语义

- 新网页显示紧凑的“初始化加工”和“导入本地”入口；打开页面本身不会创建或写入草稿。
- 点击“导入本地”先保存页面快照，通过 `/api/highlights/import-local` 的异步请求进入共享后台队列；处理完成才写入 `阅读区/浏览器高亮/` 并锁定草稿。请求键和任务编号持久保存，刷新页面或 service worker 重建后继续查询；进度和结果显示在折叠加工控件之外。
- 要求翻译就必须有实际译文，要求导读就必须有实际导读。字数、英文比例、单块是否含中文、洞察数量和文风不再阻止导入。产物齐全的可读警告可以发布并提示；原文回退或缺失导读只保留内部审计，不进入阅读区。
- 提取时保护 TeX、KaTeX/MathJax 原始公式、代码、表格、链接和图片。缺少 TeX 时保留原始 MathML/图像并提示；超过完整快照上限时停止，不静默截断。
- 标准渲染将公式文本命令中的字面下划线转义，例如 `\text{sample_count}` 转为 `\text{sample\_count}`。数学下标、代码和来源审计不改写；直接保存和生成导读均使用此规则。
- 点击初始化后，每个 URL 维护一份 `chrome.storage.local` 草稿；再次打开已有草稿时自动恢复，不重复写入初始化状态。
- 点击红色 `放弃阅读` 会删除当前 URL 的浏览器草稿、批注、随想、问答卡与页面虚拟标记，并把面板恢复为初始化前的紧凑入口；已经落盘的本地 Markdown 不在此按钮的删除范围内。
- “加工模式 / 挖空模式”在页面操作面板中选择，全局互斥；两者都关闭时选择文本不会产生标注。
- 高亮只保存文本坐标与注释元数据；页面上的 `<mark>` 是可重建的显示层。
- 点击 `保存当前版本`：`阅读区/浏览器高亮/` 只写入可直接阅读的 Markdown；高亮、评论、加工类型、挖空、问答卡、随想与状态写入项目内部 `.local-ir/browser-document-state/`，成功后锁定浏览器草稿并交给 Obsidian 接续。
- 已保存并锁定的草稿显示 `重新导入`；它真实重投插件保存的来源快照，复用已完成预处理阶段。后续人工修改过的本地文章不会被重导覆盖。
- 点击 `完成阅读`：复用与保存完全相同的 Markdown 转换、文件命名、`浏览器高亮/` 子目录、虚拟高亮和状态写入流程；只把根目录从 `阅读区/` 改为 `待归档原文/`，并把文档状态写为 `done`，成功后锁定草稿。
- 已完成草稿的 `重新导入` 会继续写回 `待归档原文/浏览器高亮/`，不会降级改投阅读区。
- 关闭标签页：脏草稿按最后一次提交目的地提交；普通草稿默认为阅读区。
- 浏览器退出时来不及提交的草稿会保留，本地扩展下次启动后重试。

普通“保存”生成的 Markdown 保留原始正文；“导入本地”生成标准化后的阅读 Markdown。两条路径都把加工状态放在阅读区外的内部状态目录，不向正文写入 `==...==`。浏览器坐标会在最终 Markdown 上重新锚定；找不到可靠位置时保留为 orphan。

“导入本地”的 `request.json`、`result.json`、`run-manifest.json` 和接口原始 `reading.md` 保存在 `.local-ir/browser-standard-preprocess/<URL 哈希>/`；阅读区只保留加入 Local IR 元数据后的最终 Markdown，不写入 JSON。

旧 `/api/highlights/capture` 与旧 `--网页全文高亮--` 产物继续保留，作为已经验证的兼容路径，不删除、不覆盖。

## 安装与运行

先启动本地服务：

```powershell
npm run app
```

然后在 `chrome://extensions` 或 `edge://extensions` 中开启开发者模式，使用 `加载已解压的扩展程序` 选择：

```text
D:\Projects\渐进阅读工作流\browser-highlight-extension
```

该 D 盘目录是唯一正式加载目录。禁止从 `.codex\worktrees` 或 C 盘历史路径加载；这些路径可能在任务迁移或清理后失效，导致 Chrome 无法重载扩展。

popup 应显示 `popup 脚本已加载 v0.5.17`。先运行 `运行诊断`，再运行 `健康检查`。扩展会探测 `37829-37849` 并保存可用端口。popup 不再控制高亮模式；初始化、导入本地和两种模式都在网页悬浮工具框中完成。浏览器链接入口与 Obsidian 都只向同一个 broker 提交 URL；抓取、标准 Markdown 处理和回执由共享服务端工作流完成。扩展不会打开内容标签页或恢复抓取 worker。

修改扩展文件后必须在扩展管理页点击一次 `重新加载`；已解压扩展不会自动读取磁盘上的新版本。普通 `http` / `https` 页面可注入，`chrome://`、`edge://`、扩展商店及其他浏览器内部页面不可注入。

开发验证：

```powershell
npm run browser-highlight:check
```

该命令检查 Manifest 和脚本语法，并运行草稿状态机及隔离端到端测试。

## 标准 Markdown 接口

“导入本地”使用下列正式链路：

```text
browserPageToMarkdown(html/pageText) 产生原始 Markdown
  -> preprocessBrowserCapture 标准接口
  -> 验证 ready 合同
  -> 阅读区最终 Markdown + 内部状态 sidecar
```

请求映射：

- `material/input`: 原始 Markdown；
- `source_type`: `browser_capture_markdown`；
- `source_metadata`: URL、标题、采集时间、采集代理、原始 Markdown SHA-256、草稿 ID 与 revision；
- `user_instruction`: 草稿中保存的用户指令，当前无专门 UI 时为空字符串。

外部 AI 只接收由 Readability/Turndown 转出的原始 Markdown、来源 URL/标题等必要来源元数据和用户指令；可见浏览器状态、DOM 原文、浏览器文本坐标和批注元数据不会发送。
